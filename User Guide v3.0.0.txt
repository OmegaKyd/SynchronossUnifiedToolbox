Synchronoss Unified Toolbox – User Guide
========================================
Version 3.0.0

This toolbox helps investigators process Verizon / Synchronoss mobile backup
returns into organized, reviewable case data (contacts, chat transcripts with
attachments, media, call logs, DV access logs, unique IPs, and more).

The original Synchronoss Toolbox was created by Rempstrom (GitHub) for a
specific case and shared to help others. The Synchronoss Unified Toolbox
builds on that work to combine the separate workflows into one automatic
end-to-end pipeline.


WHAT’S NEW IN 3.0.0
-------------------
Major cumulative changes since 2.2.0:

• Case index is a multi-section dashboard with a left navigation pane:
    Home, Call Logs, Contacts, Conversations, Compiled Attachments,
    Unlinked MMS, DV Access Logs, DV Unique IPs, VZMOBILE Media,
    Quarantined Files. Each nav item shows a record count in parentheses.

• DV Access Logs — CSVs named like “Dv Access logs mdn … .csv” (next to
  selection.zip or inside the return) are parsed into Uploads (SHA-256
  checksum rows) and Sync events, exported to DV Access Logs.xlsx, and
  shown on the index with filters. Column headers explain User IP, CDN IPs,
  checksum, LCID, and related fields on hover.

• DV Unique IPs — distinct user IPs from the DV logs with first seen, last
  seen, event count, and device(s).

• Unlinked MMS — media on disk not tied to a real message attachment token;
  Unlinked MMS.xlsx + index section with previews.

• VZMOBILE Media and Quarantined Files sections on the index (previews, MD5,
  filters). VZMOBILE supports exporting MD5 lists as .txt or .json.

• Compiled Attachments and VZMOBILE: circular ⓘ button when EXIF / extra
  metadata exists; click opens a floating metadata popover.

• Live filter counts (“xx of xxx … displayed”) on searchable/filterable
  tables; Call Logs support Direction and Date dropdown filters; media
  tables support cascading type/date/device filters.

• Pipeline is 9 stages (status line 1/9 … 9/9), including DV discovery.


=================================================================
REQUIREMENTS (Windows)
=================================================================

1. Python 3.8 or newer
   https://www.python.org/downloads/
   During setup, check “Add Python to PATH”.

2. Python packages (from the project folder):

       pip install -r requirements.txt

   (Pillow, openpyxl, pandas)

3. GPG4Win (for decryption)
   https://www.gpg4win.org
   Or install via winget (the GUI can offer this if gpg is missing):

       winget install --id GnuPG.Gpg4win -e --source winget

4. The original selection.zip from Synchronoss and the GPG passphrase
   from the #secure email (leotransfers / Synchronoss delivery).


=================================================================
HOW TO START THE GUI
=================================================================

Double-click:

       Run_Toolbox_GUI.bat

This starts the GUI without a lingering command-prompt window.

Alternative (from the project folder that contains synchronoss_parser):

       python -m synchronoss_parser.toolbox_gui

IMPORTANT:
  Do not run toolbox_gui.py from inside the synchronoss_parser folder in a
  way that skips the package path. Prefer the .bat file or:

       python -m synchronoss_parser.toolbox_gui


=================================================================
WHAT YOU NEED FROM SYNCHRONOSS
=================================================================

Typical delivery:

  • Download package (often via leotransfers.com)
  • #secure email with download password AND a separate GPG passphrase
  • Inside the download: selection.zip (keep this file as-is)

Use the original (or a copy of) selection.zip — not folders you already
unzipped yourself.

Optional but useful: DV Access Log CSV files (names like
“Dv Access logs mdn … .csv”). Place them next to selection.zip or leave
them inside the return; the pipeline discovers them automatically.


=================================================================
RUNNING THE PIPELINE (GUI)
=================================================================

The window is a single form (no tabs). Window title shows version 3.0.0.

Fields:

  Selection.zip
      Browse to the original selection.zip from Synchronoss.
      Hint: Use the original (or copied) "selection.zip" file provided by
      Synchronoss - not any of the unzipped files

  Case folder
      Choose an empty (or new) folder for this case. The pipeline creates:

          Case folder/
            original_working/   – intermediate decryption & extraction
            parsed_output/      – final case data (open this)

  GPG Password
      The decryption passphrase from the #secure email (not the download
      password, unless they happen to be the same).

  Owner name (optional)
      Account holder’s display name (e.g. Jane Doe). Shown in transcripts
      and the call log the same way other contacts are labelled.
      The owner’s phone number is auto-detected from encrypted filenames.

Click  Run

Status line shows stages 1/9 through 9/9:

  1. Extract selection.zip
  2. Discover encrypted payloads (main / contacts / quarantine)
  3. Look for DV Access Log CSVs (optional)
  4. Decrypt the .gpg payloads
  5. Extract the main content archive
  6. Convert contacts → Excel
  7. Recover quarantined media
  8. Collect media, attachments & unlinked MMS
  9. Render chat transcripts & write index.html

When finished:
  • The progress bar shows complete
  • An “Open output folder” button appears — opens parsed_output/


If gpg is not installed, the GUI offers to run:

       winget install --id GnuPG.Gpg4win -e --source winget

After install completes, you can restart the application from the prompt
so it can find gpg.

=================================================================
USING THE INDEX (index.html)
=================================================================

Open parsed_output/index.html in a browser (works offline / file://).

Left navigation (with record counts):

  • Home — owner info, high-level counts, processing details
  • Call Logs — filterable by text, Direction, and Date
  • Contacts — filterable table
  • Conversations — searchable across titles and message content
  • Compiled Attachments — previews, filters, optional ⓘ metadata
  • Unlinked MMS — media not tied to a message token
  • DV Access Logs — Uploads vs Sync Events; hover headers for field help
  • DV Unique IPs — user IPs with first/last seen, event counts, devices
  • VZMOBILE Media — cloud backup media; MD5 export
  • Quarantined Files — recovered quarantined media

Filter bars and search fields show a live “xx of xxx … displayed” count.
Many tables support click-to-sort column headers and column resize.

Inside a conversation:

  • Search messages
  • Attachments only — checkbox to show only messages that have attachments
  • Day headers hide when a filter leaves no messages for that day
  • Print — print-friendly layout:
      - Chat details at the top of page 1 (not a sticky overlay)
      - Footer: chat name on the left, page numbers on the right
        (turn off browser “Headers and footers” to hide the file path)
      - Attachments scaled for paper
  • “Return to Conversations” opens the Conversations section of the index

Contact labels show Name (phone) when a contact is known.
The owner line in the header uses Owner name when you supplied one.


=================================================================
DV ACCESS LOGS (BRIEF)
=================================================================

  • User IP — public IP of the device/user
  • CDN IPs — intermediate Content Delivery Network addresses (not the user)
  • File Checksum (SHA-256) — hash of an uploaded file (hash matching / CyberTips)
  • LCID — line / account identifier for the subscriber line
  • Uploads — rows with a file checksum
  • Sync events — check-ins / activity without a specific file upload

Unique user IPs are also summarized on the DV Unique IPs page.


=================================================================
TIPS
=================================================================

  • Always verify important findings against the original data.
  • Prefer a short case folder path (very long Windows paths can still
    cause issues with some media tools).
  • Keep original_working/ if you need intermediate files for review;
    the final product for analysis is under parsed_output/.
  • Compiled Attachments keep the original attachment filenames.
  • GPG decryption of large archives can take a long time — leave the
    window open until the status shows completion.


=================================================================
COMMAND-LINE (OPTIONAL)
=================================================================

Advanced users can still call modules directly, for example:

       python -m synchronoss_parser.full_pipeline ^
           --selection path\to\selection.zip ^
           --output path\to\case_folder ^
           --passphrase "YOUR_GPG_PASSPHRASE" ^
           --target-name "Jane Doe"

See module --help for individual tools (collect media, render transcripts,
etc.). The GUI is the supported path for full case processing.
